# Cool UI (motion and effects) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make RideRecord feel alive: animated screen changes, staggered entrances, a drifting "aurora" hero, scroll reveals and small feedback effects, without losing any accessibility guarantee.

**Architecture:** All motion is CSS, defined once in `frontend/src/index.css` as tokens, keyframes and `fx-*` classes, and applied by adding classes in the screens. Screen changes use the browser's View Transitions API through one small helper. Scroll reveals use CSS scroll-driven animations behind `@supports`, so unsupported browsers simply show the content.

**Tech Stack:** React 19, Tailwind v4, plain CSS. No new dependencies.

**Spec:** None. The user skipped the design discussion ("just dive in"), so the decisions below are the planner's calls, not something the user agreed to line by line. Background: `docs/design-system.md`, `docs/why-we-are-building-this.md`.

## Design decisions (planner's calls)

- Effects are concentrated on the landing page and on screen changes, where a demo audience sees them. Inside the app, motion is limited to entrances and feedback on actions.
- Colours, type, layout and copy do not change. Only motion and one decorative background layer are added.
- Not in this plan: dark theme, merging the two token sets in `index.css` (`@theme` and the `.rr-app` overrides), count-up numbers, loading skeletons, a frontend test runner.

## Global Constraints

- No new npm dependencies. Never run `npm install` from a Linux shell (see Landmines in `docs/design-system.md`).
- Every animation lives inside `@media (prefers-reduced-motion: no-preference)`. With reduced motion, nothing moves and all content is visible.
- Animated elements must be visible by default. An animation may start from `opacity: 0` only through a keyframe `from`, never through a base style, so a browser that does not run the animation still shows the content.
- Animate only `opacity`, `transform`, `translate`, `scale` and `box-shadow`. No layout properties, except the FAQ height in Task 4.
- Durations: 150ms (feedback), 250ms (entrances, screen changes), 600ms (bars, hero). Nothing loops except the aurora drift and the recording pulse.
- Text never sits on a moving or blurred surface with less than 4.5:1 contrast (3:1 for text 24px and larger). Decorative layers are `aria-hidden` and `pointer-events: none`.
- Status stays colour + shape + word. The existing focus ring and focus-on-heading behaviour stay.
- Each task ends with `npm run lint` and `npm run build` passing in `frontend/`.

## Review Focus

1. **Reduced motion on:** every screen and the landing page show all content at once, screen changes are instant, the aurora is still. Checked in Task 5.
2. **Browser without View Transitions or scroll timelines (Firefox):** navigation works, focus still lands on the heading, landing sections are visible without scrolling tricks. Checked in Tasks 2 and 4.
3. **Fast repeated tab taps:** tapping three tabs quickly ends on the last one tapped, with focus on its heading and no console error. Checked in Task 2.
4. **Leaving Talk while recording:** the microphone still turns off when the screen changes through a view transition. Checked in Task 2.
5. **Forced colours (Windows high contrast) and contrast over the aurora:** the aurora is hidden in forced colours; the hero subtitle keeps 4.5:1 at the darkest point of the aurora. Checked in Tasks 4 and 5.

### Task 1: Motion foundation in `index.css`

**Files:**
- Modify: `frontend/src/index.css` (add tokens to `@theme`; add a new block just above the existing `prefers-reduced-motion: reduce` block)

**Interfaces:**
- Produces: tokens `--ease-out`, `--dur-1`, `--dur-2`, `--dur-3`; classes `fx-rise`, `fx-grow`, `fx-lift`, `fx-pulse`, `fx-aurora`; the custom property `--i` (integer, stagger index).

- [ ] **Step 1: Add the tokens inside `@theme`**

```css
  --ease-out: cubic-bezier(0.23, 1, 0.32, 1); /* same curve Complaints.tsx already uses */
  --dur-1: 150ms;
  --dur-2: 250ms;
  --dur-3: 600ms;
```

- [ ] **Step 2: Add the keyframes and classes**

```css
@media (prefers-reduced-motion: no-preference) {
  @keyframes rise { from { opacity: 0; translate: 0 0.75rem; } }
  @keyframes grow-x { from { scale: 0 1; } }
  @keyframes pulse { to { box-shadow: 0 0 0 1rem transparent; } }
  @keyframes drift { to { translate: 6% 4%; rotate: 8deg; } }

  /* Stagger: set --i to the item's index. Capped so long lists never wait. */
  .fx-rise { animation: rise var(--dur-2) var(--ease-out) both; animation-delay: calc(min(var(--i, 0), 8) * 60ms); }
  .fx-grow { transform-origin: left; animation: grow-x var(--dur-3) var(--ease-out) both; }
  .fx-lift { transition: translate var(--dur-1) var(--ease-out), box-shadow var(--dur-1) var(--ease-out); }
  .fx-lift:hover { translate: 0 -2px; box-shadow: 0 8px 20px -12px var(--color-ink); }
  .fx-pulse { box-shadow: 0 0 0 0 color-mix(in oklab, var(--color-overdue) 50%, transparent); animation: pulse 1.4s ease-out infinite; }
  .fx-aurora > * { animation: drift 18s ease-in-out infinite alternate; }
}
```

- [ ] **Step 3: Add `.fx-aurora` layout (outside the media query, so the still version exists)**

`.fx-aurora`: `position: absolute; inset: 0; z-index: -1; overflow: hidden; pointer-events: none; opacity: 0.2; filter: blur(80px)`. Its children are absolutely positioned blobs. Under `@media (forced-colors: active)` set `.fx-aurora { display: none; }`.

- [ ] **Step 4: Replace the hard-coded curve in `Complaints.tsx:189`**

Change `duration-250 ease-[cubic-bezier(0.23,1,0.32,1)]` to `duration-(--dur-2) ease-(--ease-out)`.

- [ ] **Step 5: Verify**

Run in `frontend/`: `npm run lint` then `npm run build`. Expected: both exit 0. Open the app, build a draft on Complaints, and confirm the draft still slides in.

### Task 2: Animated screen changes

**Files:**
- Create: `frontend/src/motion.ts`
- Modify: `frontend/src/App.tsx:30-33` (`go`), `frontend/src/main.tsx:14-21` (`onHash`), `frontend/src/index.css`

**Interfaces:**
- Produces: `withTransition(update: () => void): Promise<void>` in `motion.ts`. It runs `update` inside `document.startViewTransition` with `flushSync` when the API exists, otherwise calls `update` directly. It resolves once the DOM has been updated (`updateCallbackDone`), never on `ready` or `finished`, because `ready` rejects when a newer transition interrupts.

- [ ] **Step 1: Write `withTransition`** as specified above. It is under ten lines.

- [ ] **Step 2: Use it in `App.go`**

`go` becomes: `withTransition(() => setScreen(id)).then(() => heading.current?.focus())`. Remove the `requestAnimationFrame` call.

- [ ] **Step 3: Use it in `main.tsx` `onHash`**

Wrap `setInApp(next)` and `window.scrollTo(0, 0)` together in one `withTransition` call.

- [ ] **Step 4: Add the transition CSS to `index.css`**

Inside the `no-preference` block from Task 1:
- `::view-transition-old(root)`: `animation: var(--dur-1) var(--ease-out) both` fading out and moving up `0.5rem`.
- `::view-transition-new(root)`: reuse `rise` at `var(--dur-2)`.
- `.rr-tab[aria-current='page'] { view-transition-name: active-tab; }` so the highlighted tab slides between positions. The nav is rendered twice, but one copy is always `display: none`, so the name is unique among rendered elements. Do not change that.

Inside the existing `prefers-reduced-motion: reduce` block add:
`::view-transition-group(*), ::view-transition-old(*), ::view-transition-new(*) { animation: none !important; }`

- [ ] **Step 5: Verify in the browser**

Run `npm run dev` with the backend up, open `#app`, and check each line:
- Tapping a tab cross-fades the screen and the tab highlight slides. Focus is on the `h1` after each change (`document.activeElement.tagName === 'H1'`).
- Tap three tabs as fast as possible: the last one tapped is shown, focus is on its `h1`, the console has no errors.
- Start recording on Talk, then tap Home: the browser's microphone indicator turns off.
- Run `delete document.startViewTransition` in the console: tabs still switch and focus still moves.
- Landing "Log a ride" enters the app at scroll position 0.

- [ ] **Step 6: Lint, build, commit** — `git commit -m "Animate screen changes with view transitions"`
